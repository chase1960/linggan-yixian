# 方法自进化闭环审查

## 当前缺口

原流程可以沉淀实际行动和结果，也可以手动修订方法，但不会说明建议来自哪个方法版本。反馈和版本之间缺少显式连接，也缺少下次验证的标准。此更新把这两条路径连接起来。

## 借鉴

- [OpenAI Agent Improvement Loop](https://developers.openai.com/cookbook/examples/agents_sdk/agent_improvement_loop)：用一次运行和反馈留下可追溯样本。
- [LangSmith 评估类型](https://docs.langchain.com/langsmith/evaluation-types)：分开收集反馈与比较版本，让原有通过案例保留为回归测试。
- [Mem0 Memory History](https://docs.mem0.ai/api-reference/memory/history-memory)：将版本历史与当前可调用版本分开。

## 工作流

1. 在「复盘与行动」选择一条记录，采纳源自方法建议的行动时会保留方法版本与当时的建议。记录自带的专属行动仍优先，不计给方法。
2. 实践后可选「达到预期 / 部分达到 / 未达到 / 没有使用」。不选择也能如常保存经历。
3. 仅当前方法版本的部分达到、未达到案例进入修订队列；已停用证据、旧版本、没有使用均不能触发修订。
4. 确认修订前写下变化、理由和可观察标准；保存时保留原版本及实际反馈来源。下一次匹配此方法且没有记录专属建议时，使用新的建议和标准。
5. 看板显示旧版和新版本的实际评估次数和分类，条件、标准和样本量不同都不等同于因果或严格 A/B 测试。

该流程不会自动改写方法、人格判断、原始材料或旧反馈。历史缺失版本不回填。未加入外部数据采集、模型训练或自动发布。测试使用虚构数据。

## 验证与发布边界

从 GitHub 当前归档版本增量修改；线上第 12 版此前未同步到此仓库。部署时请合并到线上源码，不要拿归档分支整站覆盖。执行环境不可用，本次通过隔离 JavaScript 运行器检查方法规则与构建脚本输出语法，完整 Node/浏览器测试尚未执行。恢复后在 app/ 运行 npm run build 和 npm test。
