# V4.1 十项优化说明（2026-11-24）

这份记录对应提交「把随手记跑成沉淀闭环」：不改 V4 的数据模型与权限边界，只解决阅读代码时发现的十处实际短板。

## 一、为什么改这十处

按「数字分身 / 个人数字资产沉淀」的目标回看代码，缺口集中在一句话：**内容能进来，但很难再被找到、被做成、被回流。**

- 检索是单个 `LIKE` 字符串，多关键词等于不做检索；
- 详情页按来源逐条查询，导入时逐条查重（N+1）；
- 「关联」只在前端用知识树检索，随手记之间无法互相发现，且保存时不校验编号；
- 标记完成不要求写结果，「已完成」容易变成自我宣告；
- 完成任务后没有回流知识树的出口；
- 没有周期复盘材料，收件箱积压、逾期、证据缺口只能自己翻；
- 离线包只能一次性全量，超 48MB 直接失败；
- 日历导出没有提醒；
- 出错时日志缺少请求标识；
- 构建脚本把私人姓名写进了源码（公开仓库本身即泄露面）。

## 二、逐项改动

| # | 改动 | 入口 | 关键实现 |
|---|---|---|---|
| 1 | 多词检索与命中摘要 | `GET /api/capture/items?q=` | 空格/逗号分词（≤6 词），逐词 AND；标题命中 3 分、下一步 2 分、结果 1 分排序；返回 `match.fields` 与 `match.snippet` |
| 2 | 批量读取去掉 N+1 | 详情 / 导入 | `capSelectIn` 按 200 一批 `IN (...)`；详情并行取原消息与版本 |
| 3 | 服务端关联候选 + 编号校验 | `GET /api/capture/items/:id/related`、`PATCH` | 近 120 条内按中文二元词与标题重合打分，返回共同词；保存时校验编号存在于随手记或知识树（历史关联保留） |
| 4 | 数据质量约束 | `PATCH /api/capture/items/:id` | `status=done` 需 ≥4 字实际结果；`reality` 升为 `actual` 需 ≥8 字观察；缺 `If-Match` 返回 428 |
| 5 | 经验沉淀闭环 | `POST /api/capture/items/:id/promote` | 只允许已完成任务；记录 ID 固定为 `memory-capture-<itemId>`，R2 写入后更新 D1 标记，重试不重复；带 `sourceRefs: capture_item` |
| 6 | 周复盘包 | `GET /api/capture/review-pack?days=7` | 完成/结果、逾期、收件箱、待判断观念、证据缺口、最早积压天数；输出 Markdown 与高亮列表；前端可下载 |
| 7 | 分域与增量导出 | `GET /api/portable?scope=&since=` | `all/capture/workspace/learning`；`since` 过滤表行；累计字节与文件数超限即报错并提示范围；响应头标注范围与大小 |
| 8 | 日历提醒 | 前端「日历提醒导出」 | ICS 增加 `VALARM`（默认提前 30 分钟）、`X-WR-CALNAME`、`DTEND`、类别与条目 ID；逾期任务一并导出 |
| 9 | 可观测性 | 所有响应 + `/api/health` | `X-Request-Id`、`Server-Timing`、单行 JSON 请求日志；健康检查只返回数据库/存储可用布尔与版本 |
| 10 | 构建隐私 | `scripts/build.mjs` | 私人词表移到 `.openai/private-terms.txt`（gitignore），另扫邮箱/手机号；命中即中断构建 |

## 三、兼容性与边界

- 数据结构未变，`drizzle/` 无新迁移；旧客户端仍可读取。
- 约束只作用于新的写入：历史记录里已有「未写结果的完成」不会被回溯判定，但会出现在复盘包的证据缺口里。
- `promote` 需要个人空间已初始化；未初始化返回 409，不创建半份资料。
- 检索与关联都是关键词规则，不接实时大模型，不产生因果或人格结论。
- 导出不包含令牌、令牌哈希与上传配置；分域导出时 `restore_sqlite.py` 自动只读存在的分支。
