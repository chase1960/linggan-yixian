# AGENTS.md —— 个人认知知识库的工作说明书

> 本文件是所有 AI Agent 维护这个知识库时必须遵守的最高规则。
> 人负责判断"什么对我重要"，AI 负责提取、归档、交叉引用和维护一致性。

---

## 0. 这个知识库是什么

这不是一个"对话存档库"，而是一个**自我认知的编译系统**。

- 目标：把散落在各 AI 平台（ChatGPT / 豆包 / Claude 等）的自我探索对话，蒸馏成结构化、可复利、可追溯的个人认知资产。
- 核心产物是 `wiki/` 下的认知页面，而不是 `raw/` 下的原始对话。
- 它必须平台无关：整个库是一个本地 Markdown 文件夹，复制到任何电脑、用任何文本工具都能打开。换 AI 平台不换知识库。

## 1. 三层架构

### Raw 层（`raw/`）—— 事实来源，只读
- 存放从各平台导出的原始对话、个人日记、灵感碎片。
- **AI 永远不得修改、删除、移动 raw/ 下的任何文件**，只能读取。
- 子目录按来源分：`chatgpt/`、`doubao/`、`claude/`、`journal/`、`notes/`。
- 原始文件是最终证据，任何 Wiki 结论都必须能回溯到这里。

### Wiki 层（`wiki/`）—— 蒸馏后的认知，AI 维护
- 七个分类（详见第 3 节），每个认知单元独立成页，用 Markdown 双链 `[[]]` 互联。
- AI 负责创建、补充、更新这里的页面；人负责审阅和确认。
- 所有结论必须标注来源 raw 文件路径。

### Schema 层（本文件 + 模板）—— 规则
- 本文件定义归档、更新、引用、冲突处理的全部规则。
- `wiki/*/_template.md` 定义各类页面的标准结构。
- 规则可以随实践演进，但每次修改要在 `log.md` 记录。

## 2. 处理新对话的标准流程（Ingest）

当 `raw/` 出现新材料时，严格按以下顺序执行：

1. **通读**：完整阅读新材料，不跳过、不凭标题臆断内容。
2. **检索现有 Wiki**：先列出 `wiki/` 中所有相关页面，判断哪些洞察是"已有模式的新证据"，哪些是"全新发现"。
3. **提取**：按第 4 节的提取清单，抽取洞察、模式、价值观、追问、转变、实验、实体。
4. **增量更新**（不要重建）：
   - 已有页面 → 补充新证据、更新 `updated` 字段、在页面内追加演变记录，**绝不直接覆盖旧结论**。
   - 全新内容 → 用对应 `_template.md` 创建新页面。
5. **建立双链**：在相关页面之间补 `[[]]` 交叉引用；发现页面间隐含关联时主动连接。
6. **更新导航**：同步更新 `index.md`（若出现新的重要主题）和 `timeline.md`（若出现认知转变节点）。
7. **写日志**：在 `log.md` 顶部以只追加方式记录本次处理（日期、来源、新建页、更新页、待人工确认项）。
8. **汇报**：列出新建/更新了哪些页面，以及哪些内容置信度低、需要人来确认。

## 3. Wiki 七个分类的判定标准

| 目录 | 收什么 | 判定问题 |
|---|---|---|
| `insights/` | 一次具体的"啊哈"发现，颗粒度小、来自某段对话 | "这段对话让 ta 新意识到了什么？" |
| `patterns/` | 跨对话反复出现的思维/情绪/行为/关系模式，需 ≥2 个证据 | "这个倾向是不是出现过不止一次？" |
| `values/` | 价值观、核心动机、人生优先级及其权重变化 | "ta 真正在乎/逃避/追求的是什么？" |
| `questions/` | 持续追问、尚未解决的开放性问题 | "ta 是否在多段对话里反复绕回同一个问题？" |
| `transitions/` | 明确的认知/态度转折点（Before→After） | "这里是否发生了'我以前认为…现在认为…'？" |
| `experiments/` | 为改变而做的具体尝试及其结果 | "ta 是否采取了行动来验证某个想法？" |
| `entities/` | 对 ta 有重要影响的人、书、概念、工具、事件 | "这个东西是否反复出现并影响了 ta 的思考？" |

**拿不准归类时**：优先放 `insights/`，并在页面标注 `#待归类`，等证据积累后再升级为 pattern 或合并。

## 4. 从自我探索对话中提取什么

重点提取（这是本库区别于通用知识库的关键）：

- **情绪信号**：反复出现的情绪、触发情境、情绪背后的真实需求。
- **语言模式**：高频词、绝对化表述（"总是/永远/必须"）、自我否定或自我辩护的句式。
- **内在冲突**：理性与感受、想要与应该、短期与长期之间的拉扯。
- **核心动机**：表面诉求之下的深层需求（参考：被认可 / 自主感 / 安全感 / 连接感 / 胜任感 / 意义感）。
- **认知变化**：观点、自我评价、对人对事判断的前后差异。
- **未说出口的假设**：对话中默认成立、但从未被检验的前提。
- **行动与结果**：承诺要做的事、实际做了的事、结果与预期的差距。

不要提取：纯信息查询、寒暄、与自我无关的工具性问答、一次性事实。

## 5. 溯源与置信度（重要）

每条提炼内容必须标明它是怎么来的：

- `extracted`：对话中用户明确表达过，可直接引用原句。
- `inferred`：AI 基于多处表述推断的，用户没有直接说过——**必须标注，供人审阅**。
- `ambiguous`：表述模糊、存在多种解读——**必须标注，并列出可能的解读**。

页面 YAML 中的 `confidence` 字段：
- `high`：用户明确表达且多次出现。
- `medium`：有明确表达但只出现一次，或是较有把握的推断。
- `low`：推测成分大，需要用户确认。

## 6. 冲突与演变处理（成长轨迹的核心）

当新材料与旧结论冲突时，**这往往是最有价值的成长信号，绝不能覆盖删除**：

1. 保留旧结论，注明"截至 YYYY-MM-DD 的认知"。
2. 写入新结论，注明来源和时间。
3. 在页面"## 演变"区域记录：`旧认知 → 触发来源 → 新认知 → 转变原因`。
4. 如果转变足够重大，同时在 `transitions/` 单独建页，并登记到 `timeline.md`。

## 7. 页面与格式规范

- 所有页面使用 Obsidian 兼容的 YAML frontmatter（字段见各 `_template.md`）。
- 文件名用中文短语概括，避免日期堆砌（如 `面对权威时的沉默模式.md`）；同主题加日期区分时用 `标题-2026-03.md`。
- 双链用 `[[]]`，标签用 `#标签`，标签体系保持稳定、不要每次发明新词。
- 引用原始对话时写明相对路径，例如：`来源：raw/chatgpt/2024-03-15-xxx.md`。
- 无法确认的内容明确写"待核实/待确认"，禁止编造用户没说过的经历或结论。

## 8. 索引与时间线维护

- `index.md`：知识库的"当前版本的我"——核心画像、活跃主题、各分类入口、最近更新。每次 ingest 后检查是否需要刷新。
- `timeline.md`：只登记**认知转变节点和重要里程碑**（不是每次处理都写），按时间倒序或正序保持一致。
- `log.md`：只追加的操作流水，格式见文件内说明。

## 9. 隐私与安全

- 本库包含高度私人内容，默认只在本地处理，不主动上传到任何公开云服务。
- 若需要用云端 AI 处理，先由人确认该批材料无敏感信息（姓名、公司、隐私事件可先做化名替换，化名映射单独保存、不随库同步）。
- 不把任何 API Key、密码写入库内。

## 10. 禁止事项

- 禁止修改/删除 `raw/` 原始文件。
- 禁止用新结论覆盖旧认知而不留演变记录。
- 禁止在没有来源的情况下生成关于用户的结论。
- 禁止一次性大规模重命名/重组而不在 `log.md` 说明。
- 禁止为了"页面好看"而编造交叉引用；没有真实关联就不链接。
- 信息不足、或某个判断会显著影响整体结构时，暂停并向用户提问，而不是自行决定。

## 11. 定期健康检查（Lint，建议每月一次）

- 找出没有任何入链的"孤儿页面"，判断是否该补链接或合并。
- 检查 `#待归类`、`confidence: low`、`待确认` 的页面，提请用户处理。
- 检查同一主题是否被拆成了多个重复页面，必要时合并。
- 检查 `questions/` 中哪些问题已经有了答案，更新状态或转为 transition。
- 在 `log.md` 记录本次健康检查结果。
